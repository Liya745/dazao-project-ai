# 首版详细设计：角色创建、编辑与试聊

日期：2026-10-14。本文落实总体方案的第一阶段，同时约束本地 MVP 的实现范围。

## 1. 仓库与目录

本项目为独立 Spring Boot 后端项目，Vue 前端放在后端根目录的 dazao-ui/ 中；整个 dazao-project-ai/ 可作为新仓库一次提交。根 pom.xml 管理后端，dazao-ui/package.json 与 package-lock.json 管理前端。配置示例可提交，真实密钥、数据库、依赖与构建产物排除提交。gpt/ 仅保存方案、设计及验证文档。

## 2. 首版的使用流程

1. 在网页注册独立账号、登录。
2. 在工作室选择原创、已有 IP 或功能型角色，描述需求；IP 角色补充作品、版本和资料。
3. 生成一份完整角色草稿，在编辑器修改字段。
4. 锁定需要保留的字段，选中需要重生成的字段，生成其余内容。
5. 保存后出现在“我的角色”；可以编辑、复制、删除及导出 Character Card V2 JSON。
6. 为角色创建试聊会话，使用保存时的角色版本；聊天记录在服务端保存。
7. 修改角色形成新版本，已有会话保留原设定。要使用新版本则创建新会话。

角色草稿不等于已保存角色，用户主动保存后才进入角色库。生成或编辑失败时保留当前输入，不清空用户劳动。

## 3. 页面与交互

角色工作室：左侧为导航和账号，中间是需求及角色字段编辑，右侧预览角色身份、简介和开场白。创建与编辑共用工作台。字段具有锁定控制；局部重生成需显式选择字段。

我的角色：显示真实保存的角色，提供搜索、继续编辑、复制、删除、开始试聊与导出。没有保存角色时展示创建引导，不放假装为用户数据的示例。

角色试聊：显示会话绑定的角色和版本、开场白、历史记录和流式回复；可切换原有会话，也可新建。网络或模型失败显示状态及重试入口，不用固定文本冒充模型回答。

视觉方向：暖纸色、炭黑与朱红，强调创作编辑器和角色预览，桌面支持三栏，移动端顺序排列。提供清晰焦点、表单标签、键盘操作和减少动画选项。

## 4. 角色字段

| 字段 | 用途 |
| --- | --- |
| name | 显示名称 |
| description | 身份、背景、动机和角色介绍 |
| personality | 性格、习惯及行为倾向 |
| scenario | 世界观与当前互动场景 |
| firstMessage | 角色开场白 |
| messageExample | 体现说话方式的示例对白 |
| appearance | 外观与头像描述 |
| speechStyle | 措辞、语气、长度等表达规则 |
| sourceType | original / ip / assistant |
| work、canonVersion | IP 作品与设定版本 |

角色内容为文本数据，展示时按文本渲染。公开分享、自动画像、工具执行、声音与 Live2D 留在后续阶段。

生成器使用固定字段白名单、JSON 输出和服务端验证。局部重生成仅写回用户选中的非锁定字段，其他字段由服务端保持原值，不能只靠提示词要求模型遵守。IP 资料不确定时保留不确定性，用户提供的改编要求与原作内容区分。

## 5. 后端职责和持久化

采用 Spring Boot 3.5 系列、Java 17、Spring Security、Spring JDBC 和 LangChain4j。Vue/Vite 独立构建，生产打包可将 dazao-ui/dist 放入后端静态资源，形成一个 Jar。本轮是本地 MVP，尚未作为公网生产服务验收。

本地使用 H2 文件数据库，保存独立账号、角色、会话和聊天轮次，重启可恢复。生产 MySQL 迁移与 Redis 缓存配置在部署阶段设计，不能直接把本地 H2 方案视作生产数据库。

角色归属由服务端登录身份确定，不接受前端 ownerId。所有读取、修改、删除和会话接口均检查归属。保存带版本号，过期编辑返回冲突提示。会话保存角色快照，避免修改角色污染已有会话。

认证使用 Spring Security 会话 Cookie（HttpOnly）和 CSRF；开发前端通过 Vite 代理访问同一后端，密钥不进入浏览器。后续多实例部署再评估会话共享。本地默认仅监听 127.0.0.1。

## 6. 接口方向

| 接口 | 行为 |
| --- | --- |
| /api/auth/* | 注册、登录、注销、当前身份和 CSRF |
| GET /api/status | 是否具备模型配置，不返回密钥 |
| POST /api/characters/generate | 需求、现有草稿、选中字段和锁定字段，返回完整草稿 |
| GET/POST /api/characters | 列表与保存 |
| GET/PUT/DELETE /api/characters/{id} | 查询、带版本更新与删除 |
| POST /api/characters/{id}/copy | 复制为自己的新角色 |
| GET /api/characters/{id}/export | Character Card V2 JSON |
| GET/POST /api/conversations | 会话列表与创建 |
| GET/DELETE /api/conversations/{id} | 历史与删除 |
| POST /api/conversations/{id}/messages | SSE：delta、done、error 事件 |

角色创建使用普通 JSON 响应，聊天使用 POST + SSE，用户消息不放在 URL。模型配置来自环境变量，配置缺失时返回明确错误；不自动访问旧站密钥或回退成演示生成器。首版 API 实现以 README 的实际完成清单为准。

## 7. 模型调用与成本

复用 OpenAI 兼容模型接口，由 LangChain4j 负责调用。生成任务采用 JSON 模式并进行字段验证，聊天任务依据角色快照构造身份、场景、表达方式、对白例子和最近完成的聊天轮次。

设置输出上限、超时、并发限制和每用户请求额度。模型原始错误和密钥不回传浏览器。未完成的聊天轮次带失败状态；保留用户输入和可用历史。自动摘要、向量检索和长期关系记忆后续验证。

不同供应商的 JSON 模式与流式能力需验证。仅仅接口地址格式相同，不代表所有模型功能兼容。

## 8. 验证与上线边界

自动验证：账号认证与 CSRF、角色归属隔离、局部重生成锁定、版本冲突、会话快照、持久聊天记录和角色卡导出。使用测试替身验证接口，不向真实供应商发送自动化测试请求。

人工/浏览器验证：注册登录、完整创建编辑保存试聊流程、异常提示、宽屏与窄屏布局、前端构建。真实模型质量需配置用户选择的 API Key 后，选 5 个不同角色各聊约 20 轮；未执行时明确记录。

本轮不部署到云服务器，不接入微信、QQ，不更改旧大枣或 Saya。新增依赖已获得用户授权。下一阶段通过体验验收后再验证 LangBot 接入与服务器资源。
