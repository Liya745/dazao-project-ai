## 部署实现

Vue 部署版本使用 `/dzproject/` 作为构建 base，API 统一从 Vite BASE_URL 拼接；Spring Boot 使用相同 context-path。Cookie 名为 DZSTUDIOSESSION、路径为 `/dzproject`，与其他站点账号隔离。

后端与前端打为一个 Jar，由一份 `deploy/compose.yaml` 管理。复用服务器已有 Temurin Java 17.0.20 镜像，启动前校验镜像 ID，未拉取新镜像。Jar SHA-256：

`16dda095ac1efd7bfc7447187769ede4c4a4759793bb37709579372b5e592a3a`

专用端口只发布到 `127.0.0.1:18199`，宿主机 Nginx 转发 `/dzproject/`，不去掉路径前缀。没有开放数据库或新应用公网端口，没有调整 DNS。

仅替换原大枣路径入口片段，新增大枣专用代理与限流文件；原宿主机 server、Saya 回调 location 和原有配置文件保持原字节。Nginx 语法验证成功后平滑 reload。

注册按 IP 限制 3 次/分钟，登录 10 次/分钟，角色生成 5 次/分钟；只应用于大枣指定路由。聊天代理关闭缓冲，读取超时 180 秒，并设置大枣的 CSP 等响应头。实现参考 [Docker Compose 项目隔离](https://docs.docker.com/compose/how-tos/project-name/) 与 [Nginx 代理缓冲配置](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_buffering)。

容器使用 UID 10001、只读根文件系统，数据目录专用。内存硬上限 384 MiB、CPU 上限 0.5 核、临时空间上限 32 MiB、日志最多 3 × 5 MiB。收尾时内存约 153.9 MiB，CPU 约 0.13%；该测量不是并发性能压测。

## 日常运行与回退

```sh
cd /usr/dazao-character
sh scripts/start.sh
docker compose -p dazao-character -f compose.yaml logs --tail 100 studio
```

需要恢复旧大枣入口时，在该目录执行 `python3 scripts/ingress.py rollback`。回退前会检查安装后的配置摘要，避免覆盖后续修改；新站数据仍保留。原入口备份位于 `backups/ingress/`。

H2 一致性备份需要停新项目 studio 后复制数据库文件，再启动。不要直接拷贝运行中的数据库作为一致性备份，也不要全局 Docker 清理或操作 Saya 的数据。
